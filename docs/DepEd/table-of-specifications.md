# MathVenture Table of Specifications

> **Document status:** Draft for curriculum and assessment validation
> **Subject:** Numeracy / Mathematics
> **Grade:** Kindergarten
> **Grading period:** 1st to 4th
> **School year:** 2025–2026
> **Scope:** 9 topics and 82 game activities currently cataloged in MathVenture

## 1. Purpose and use

This document maps MathVenture activities to learning competencies and to the
points/items (POIs) used in a Table of Specifications (TOS). It is a working
alignment document, not a claim of DepEd approval.

The TOS matrix is competency-based. Games are treated as learning activities
and sources of observable evidence; they are not automatically equivalent to
grades or examination items. One game may support several competencies, and
several games may support the same competency.

The official curriculum version, competency wording, competency codes, item
allocations, cognitive-level assignments, and mastery rules must be checked by
the Kindergarten teacher and school assessment lead before submission or use
for grading.

The topic names in this draft are MathVenture's working catalog labels. They
must be cross-checked against the official curriculum domain or strand; a game
topic is not automatically an official DepEd competency.

## 2. Reference format

The matrix below follows the supplied school TOS reference: competency rows,
time/frequency, number of items, percentage, and item numbers distributed by
level of cognition.

Markdown does not support merged table cells, so the grouped **Level of
Cognition** heading is represented by six separate columns.

In this document, **POI** means the numbered point/item opportunity assigned to
an assessment task. If the school uses a different definition for POI, replace
this definition consistently throughout the document.

### TOS validation notes

- Every POI should be assigned to one cognitive-level column only unless the
  school defines POI differently.
- The cognitive level describes the learner's demonstrated thinking, not the
  visual complexity or theme of the game.
- The 20 POIs are assessment opportunities, not a requirement that only 20
  games may be used for instruction.
- The revised draft deliberately includes Analyzing, Evaluating, and Creating
  opportunities through pattern completion, comparison judgment, and the Little
  Color Artists performance task. These assignments still require validation by
  the Kindergarten teacher and should not be forced into a game score.
- The added competency rows are working assessment descriptions. Replace them
  with the exact approved curriculum wording and codes before submission.

## 6. Standard game specification

Each game entry should be completed using the following fields. The same
format is used for every topic and every game.

| Field | Required specification |
|---|---|
| Game ID | Stable ID from the game catalog, for example `colors:0` |
| Catalog title | Learner-facing game title |
| Component | Source component used by the game |
| Curriculum domain | Official DepEd domain or strand |
| Competency code | Exact code from the approved curriculum guide |
| Competency | Exact official competency wording |
| Unpacked objective | Observable learner behavior beginning with “Given…” or “The learner…” |
| Content | Mathematical concept, attribute, number range, or representation |
| Learner action | Click, drag, match, sort, count, order, construct, or explain |
| Response type | Selected response, constructed response, performance, or observation |
| Difficulty | Beginner, developing, or advanced; define the criteria |
| Rounds/items | Number of valid evidence opportunities |
| POI assignment | TOS item number or item range |
| Cognitive level | Remembering, Understanding, Applying, Analyzing, Evaluating, or Creating |
| Evidence captured | Correctness, independence, attempts, hints, errors, and completion |
| Scoring | Raw score and maximum score; do not assume every game is worth one point |
| Mastery rule | Teacher-approved performance threshold or descriptive criterion |
| Feedback | Learner feedback and suggested teacher intervention |
| Language | English, Filipino, or bilingual presentation |
| Accessibility | Audio, text, contrast, motor, timing, and device considerations |
| Assessment role | Instruction, practice, formative evidence, or summative evidence |
| Validation status | Draft, teacher-reviewed, revised, or approved for use |

## 9. Validation checklist

Before the document is submitted or used for grading, confirm that:

- The official curriculum version and competency codes are recorded.
- Every competency statement is copied accurately from the approved source.
- Every game actually measures the competency assigned to it.
- POIs are assigned to specific prompts, rounds, or observable performances.
- No POI is duplicated across cognitive-level columns unless explicitly
  permitted by the school's TOS convention.
- The number of items and percentages total 20 and 100%, respectively, for
  this draft matrix.
- Game scores are not treated as learner grades without an approved scoring and
  reporting policy.
- Free-play practice is separated from classroom assessment evidence.
- English and Filipino instructions have been reviewed for accuracy.
- Accessibility and device limitations have been documented.
- A Kindergarten teacher, school assessment lead, and appropriate school or
  division reviewer have checked the final mapping.

## 10. Implementation notes for MathVenture

The current application records topic, game, order, score, and maximum score.
To support this TOS fully, the assessment record should eventually be able to
associate results with competency codes, POIs, item-level evidence, cognitive
level, response type, hints, attempts, and validation status.

The current catalog assigns one maximum point to every game. That value should
not be used as the final TOS weight until the actual number and quality of
evidence opportunities in each game have been reviewed.
